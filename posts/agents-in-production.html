Everyone's Demo Works. Almost Nobody's Agent Survives Production.

September 2026

Every agent demo follows the same arc. Someone types a request, the model reasons out loud, calls a tool, gets a clean response, and produces the right answer in under ten seconds. It looks like magic, because it is a magic trick — the input was chosen to work.

Then you put the same agent in front of a real business with real data, and the first thing that happens is someone types a request that's ambiguous, or a tool call returns a 500, or a downstream API rate-limits you mid-task, or the user changes their mind halfway through and expects the agent to notice. None of that shows up in a demo. All of it shows up in week one of production.

Building automation for small businesses, I've stopped thinking of the model as the hard part. The model is the easy 20%. The other 80% is the stuff that never makes it into a launch tweet:

  • Failure containment. What happens when a tool call fails — does the agent retry blindly, hallucinate a plausible-looking result, or surface the failure honestly? Most frameworks default to the worst of the three unless you explicitly design for the third.
  • Idempotency. If the same task gets triggered twice — a webhook fires twice, a retry happens after a timeout that actually succeeded — does your agent send the same email twice, double-book the appointment, double-charge the invoice? This is the single most common production bug I see in agent systems, and it's invisible in every demo because demos don't retry.
  • Knowing when to stop and ask. A good agent has an escalation path. A demo agent barrels forward with its best guess because "asking a clarifying question" doesn't make for a compelling fifteen-second clip.
  • Observability. When something goes wrong three weeks after launch, can you actually see what the agent saw, what it decided, and why? If the answer is "check the logs" and the logs are a wall of raw model output, you don't have observability, you have a haystack.

None of this is a knock on the models themselves — they've gotten remarkably good at the reasoning and tool-use part of the job. But "the model can do it" and "the system around the model can be trusted to run unattended" are two completely different claims, and the industry conversation mostly stays on the first one because it's the one that's easy to show off.

The teams shipping agents that actually stay running aren't the ones with the fanciest prompt. They're the ones who treated the agent like any other piece of production software: instrumented, tested against edge cases on purpose, with a clear answer for "what happens when this breaks at 2am and nobody's watching."

That's the unglamorous work. It's also the whole difference between a demo and a dependency.
